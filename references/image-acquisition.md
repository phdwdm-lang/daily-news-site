# 取图与逐条验收

适用于选定的每条 `featured`、`personal`。目标是让图片解释本条内容；允许有证据的无图，不用装饰图凑齐。审计字段见 [run-audit.md](run-audit.md)。

## 获取与选择

1. 按条目 URL／产品身份检查采集保存的 newsletter 图像候选及其上下文，再读取本条实际原文。原文不可访问时保存实际响应和限制，再查 newsletter 或已知官方公告／产品页；不能用未访问的链接充当检查结果。
2. 零候选、空 `alt`、抓取不到 `<img src>` 都不等于无图。按页面实际结构检查 `currentSrc`、`srcset`、`data-src`、`picture`、Open Graph 图像及链接的官方页；需要动态渲染时再使用浏览器。图像候选的标题相近不证明身份或内容匹配。
3. 优先功能截图、界面、评测图表和真实演示画面。排除广告、追踪像素、导航、无关人物照及只重复标题的装饰图。保存候选 URL 和具体取舍；不是要求展示原文的每张图。
4. 使用已核实的同一身份缓存或 `scripts/assets.py` 下载。实际查看本地图片后核对内容、身份、尺寸和裁切，再确认 `visual_verified`。只有成功下载但没看图，或只核对文件格式，不能标为已选完成。候选 URL 应对应缓存记录的 `asset_url`／`resolved_url`。

默认回查范围止于 newsletter、本条原文，以及最多两个直接相关官方页面；每个失败来源最多重试一次。达到范围仍无合适图就保留无图和具体结果；不无限搜索，也不因缺图改新闻排序。需扩大范围时以明确的新线索为依据，并记录原因。

独立来源读取可以并行；`scripts/assets.py` 写素材及共享缓存索引时使用站点锁，应逐项执行。遇到“另一个更新正在提交，请稍后重试”，待前项完成后重试该项；这属于本地写入冲突，不能记成来源不可用或图片下载失败。

本次运行内保留原响应、提取的候选元数据／上下文或浏览记录，供审计按哈希绑定。每条 `review` 必须区分：

| `decision` | 实际含义 |
| --- | --- |
| `selected` | 已选定、下载／复用并实际核对的候选，绑定真实缓存身份。 |
| `no_candidates` | 已检查来源，确无可提取候选；来源不可读也要保存响应及回查结果，不能声称全文无图。 |
| `all_rejected` | 存在候选，但逐项因无关、仅装饰等原因排除。 |
| `download_failed` | 有适用候选且实际尝试获取，均未取得可用文件；保留失败记录。 |

无图另写本条的 `missing` 说明，不能批量填“来源无图”“无合适配图”当作已经查找。说明应足以区分来源不可访问、未发现候选、候选不适用和下载失败。不能虚构失败，或把尚未尝试的下载列为失败。

## 头像缓存未命中

先核对作者的稳定身份，再查本人公开资料页／机构团队页，默认最多两个直接相关来源，每个失败来源最多重试一次。缓存不存在只说明尚未保存，不等于没有可用头像。取得后实际看图确认作者身份并写入身份缓存；仍无法取得时，`missing_avatars` 中保留本人的具体缺失说明及 `review.sources`，每个来源记录真实 URL、`checked`／`unavailable` 和本地证据。不能用同名他人照片或无图默认理由填补。

## 候选页面检查

来源门禁通过后，使用 Ego Lite 在实际候选中切换**全部重点**，展开／滚动查看每条个人内容。每条记录 `media_checks`：以原文 URL 绑定，图片路径必须与单期数据一致；有图应恰好渲染一张条目配图并成功加载，无图应为零。按需滚动触发懒加载，检查实际图片的 `complete`、`naturalWidth` 与可见画面，不能只检查 HTML 中存在 `src`。

保存桌面与窄屏的真实截图，覆盖本轮新增／改动的图片；核对图片不串条目、不变形、不裁掉关键内容，个人全文仍可读。重建候选或调整任何素材／内容后，重新进行同一候选的验收并签收；旧检查不能沿用。
