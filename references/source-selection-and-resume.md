# 来源日期与续跑

## 两种选择

- 不传日期：`latest`，整理日为北京时间今天，读取检查时已经发布的最新可得来源；即使官网含定时预告，也不取未来发布日期。
- 显式 `--date YYYY-MM-DD`：`as-of`，截止时间为该日期下一天北京时间零点（严格小于）。各 newsletter 选截止前最近一期；当天无新刊可以用前一期，保留真实发布日期与替代原因。
- 显式 `--mode latest --date YYYY-MM-DD` 仅用于有意指定整理日而仍取最新；必须公开该模式，不能冒充历史回采。时区默认 `Asia/Shanghai`。

Rundown 先检查 RSS 中全部可用期次；TLDR 与 Superhuman 从真实归档入口及页面提供的后续链接查找，最多 24 页。RSS 保留期数与官网归档覆盖有限；找不到时保存缺失状态，不推测文章地址、不以当前内容代替。每家保存选择模式、截止时间、候选/真实响应与所选期次。

Builders 在历史模式为三个 feed 分别查截止之前最后一次 GitHub 提交，保存查询证据、不可变原文地址及提交时间；再检查 feed 更新时间和已知人物、帖子、节目、博客时间，拒绝截止后的内容。最新模式读取检查时最新公开 feed，同样拒绝已知未来时间。来源发布时间与整理日期始终分开。

## 运行恢复

在项目使用 `python3 scripts/workflow.py init`；历史补跑加 `--date`。保留返回的真实运行目录，失败后运行 `status --run-dir RUN` 与 `collect --run-dir RUN`。采集写入编号尝试，成功分支可复用，失败或部分分支单独重试；不覆写旧响应。协调器默认使用项目内与安装版同步的 Skill 源。

`packet --run-dir RUN` 用于定位下一步、来源和检查点。新实例按配置使用当期上下文快照；通用模式没有待办。恢复输出及快照可能包含私人信息，仅在本实例使用，不复制到共享包或公开日志。初次编辑仍须完整读公开资讯来源，不以恢复摘要替代正文；个人参考只读已确认资料和用户选定范围，不因恢复而扫描更多会话。

依次登记 `inputs → editorial → media → audit → preview → review → published`；用 `checkpoint --run-dir RUN --phase 阶段` 并传入该阶段真实 issue、工作稿、审计或候选。完整命令与恢复实例见项目 `验收与运行说明/断点续跑.md`。素材、审计、浏览和提交阶段调用现有真实门禁，不能以状态标志制造通过。

来源、上下文、稿件、素材、审计或模板的摘要变化，会使所属阶段及后续阶段失效。资料／配置改变或取得本次动态来源后，用 `context_profile.py snapshot --run-dir RUN --refresh` 刷新快照，再重走失效阶段。旧实例的 v1 Page／HTML 审计仍按其原规则读取，不把旧任务改标为新确认资料。

候选保存在本次运行目录的 `previews/`，签收引用该持久路径，避免临时目录清理后无法恢复。状态与事件记录只帮助定位，不是浏览证据。线上上传独立于本地 published 检查点，仅在本实例选择并配置线上更新后执行，还须核验真实线上版本。定时运行依赖本机、App 与浏览工具可用，读取或验收失败时保留上一版并报告；新实例不继承别人的调度。
